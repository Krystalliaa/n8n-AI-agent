
# Repository Memory\n\n## Nextcloud Home Server (Raspberry Pi 4B)\n\n**Project:** Self-hosted Nextcloud instance on a Raspberry Pi 4B (4GB RAM), headless, WiFi-only, no ethernet.\n\n**Hardware:**\n- Boot media: microSD card (Raspberry Pi OS, headless)\n- Persistent storage: 1.9TB USB SSD mounted at `/mnt/ssd`\n- Remote access: Tailscale (wlan0, power-save disabled persistently)\n\n**Stack:** Four Docker containers managed via Docker Compose — `db` (MariaDB), `redis`, `app` (Nextcloud, port 8080), `cron` (Nextcloud background jobs). All persistent data uses bind mounts into `/mnt/ssd/nextcloud/{db,redis,html,data}`. Secrets in a single `.env` file shared by the Compose stack and automation scripts.\n\n**Key file locations:**\n- Compose file and `.env`: `/mnt/ssd/nextcloud/`\n- Backup script: `/usr/local/bin/backup_nextcloud.sh` (cron: daily 03:00)\n- Restore script: `/usr/local/bin/restore_nextcloud.sh` (manual)\n- Backup archives: `/mnt/ssd/backups/` (30-day retention)\n- Network monitor logs: `/mnt/ssd/network-monitor/network_YYYY-MM-DD.log`\n\n**Compose service names vs container names:**\n- Service `app` → container `nextcloud`\n- Service `cron` → container `nextcloud-cron`\n- `docker compose` subcommands require service names; `docker exec` uses container names.\n\n**Critical operational knowledge:**\n- Raspberry Pi Imager regenerates PARTUUIDs on re-flash but does NOT update `/etc/fstab`. After any re-flash, reconcile `fstab` against `blkid` output before booting.\n- WiFi power-save mode causes multi-minute reachability drops with no log trace (no disconnect events, stable IP, strong signal). Power-save is disabled persistently.\n- Nextcloud container ships a pristine reference copy at `/usr/src/nextcloud/` — use for diff and file recovery after restore without external download.\n- SSD mount uses `nofail` in `/etc/fstab` so a disconnected SSD does not block boot.\n- Backup must include `config.php` (in `html/`) — it carries instance ID, secret, and password salts.\n- Bind mounts require rsync-based backup; named-volume backup patterns (docker run -v) are inapplicable and fail silently.\n\n**Documentation:** `docs/nextcloud-home-server.md`\n
